# 学习路径与经营报表

## 学习路径与先修条件

教务在「学习路径」建立草稿，选择 2 至 30 门本学习空间已发布的课程，按培训顺序排列。每门课只出现一次。发布后固定顺序和先修条件，学员可查看当前进度、需先完成的课程和各步班期。

教务从发布路径的步骤进入「查看班期 → 为此步骤开班」，班期沿用该课程当前发布版本，也可通过接口指定已有发布版。学员完成前面所有课程后，会解锁相应班期。已有的同课程结业记录可作为先修依据。结业状态随历史学习资格保留，证书效期由验真单独计算。

系统在首次报名、代报名、企业席位激活和换班时检查目标班期的先修条件。发现缺课时返回未完成课程，原有报名或企业分配继续保留。由「班期」独立开班时可创建常规班，不关联某条学习路径。

## 课程经营与部门完成率

教务在「课程经营」按班期查看当前容量、期间入班、期间结业、转出、退班和期末完成率，可按课程筛选。企业管理员从本公司的「部门完成率」查看部门及公司合计，并按班期筛选。企业报表统计通过该公司合同激活的学员资格，沿换班链追踪后续班期。

| 指标 | 口径 |
| --- | --- |
| 期间入班 | 入班时间落在所选起止日期内，包括换班产生的新报名 |
| 期间结业 | 结业时间落在所选日期内，包括此前已入班的学员 |
| 期末有效报名 | 截止日结束前已入班的有效资格，含已结业，排除已转出的原报名、已退班和未入班候补 |
| 期末有效学员 | 可按部门查看有效学员去重人数，同一名学员在多个班期可以有多份有效报名 |
| 完成率 | 截止日已结业的有效报名数除以期末有效报名数，分母为零时留空 |
| 期间退班和转出 | 已入班的资格在期间内退班，或换班至另一个报名 |

日期采用 UTC 并包含起止当天。部门报表的「报名明细」可切换期末有效和退班、换班历史，名单可导出 CSV。历史明细只展示截止日之前已发布的考试采用分。报名明细是截至日期的名单，能与期末有效数对账。起始日期用于报表里的期间指标。

## HTTP 接口

接口沿用工作台会话和 CSRF 令牌，列表通过 `after` 与 `next_after` 分页。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/learning-paths`、`GET /api/learning-paths/{id}` | 列出路径及其有序步骤，读取本人的学习进度 |
| `POST /api/learning-paths` | 教务用 `code`、`title`、`description` 和有序 `course_ids` 创建草稿 |
| `PUT /api/learning-paths/{id}` | 按 `version` 更新草稿的名称、说明和课程顺序 |
| `POST /api/learning-paths/{id}/publish` | 按 `version` 发布 |
| `GET /api/learning-paths/{id}/steps/{step}/cohorts` | 查看该步骤班期 |
| `POST /api/cohorts` | 新建班期可传 `path_step_id` |
| `GET /api/reports/courses` | 教务按日期及可选 `course_id` 查看课程经营 |
| `GET /api/companies/{id}/reports/departments` | 按日期和可选 `cohort_id` 查看获准访问的企业报表 |
| `GET /api/companies/{id}/reports/enrollments` | 可按 `cohort_id`、`department_id` 和 `view`（`all`、`effective`、`history`）查明细 |

报表的 `from`、`to` 使用 `YYYY-MM-DD`。省略时，截止日取 UTC 当天，起始日取截止日所在月份的第一天。

## 复跑验收

使用独立的 `learning_test_` 数据库完成迁移并启动工作台。

```sh
python3 tests/paths_reports_http.py http://127.0.0.1:8080
```

验收覆盖先修路径从锁定到开放、三种报名入口的条件校验、部门有效报名合计与名单核对、换班只计当前资格、退班成绩保留，以及分开统计前一天的入班和当天的结业。
