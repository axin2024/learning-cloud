## A14 容量

2026-11-27 在单台 Windows 11（26200、22 个逻辑处理器）使用本机回环地址。IIS Express 10.0.26013.1000 转发到 PHP 8.2.30 FastCGI，最多 32 个实例，启用 OPcache，关闭 IIS 输出和内核响应缓存。MySQL 8.4.13 与压测端运行在同一台机器。公开接口每次都读 MySQL。客户端为 Python 3.14.3 和 aiohttp 3.14.4。

25 个小组各用独立登录会话串行提交 400 份带新尝试号的作品，得到 10,000 个不同的提交编号。500 名并发匿名客户端查询 25 个编号，包括有效和已撤销两类。每波同时放行 500 个请求，混合及写满阶段各六波，逐条检查状态和撤销后的公开字段。

| 阶段 | 成功 / 总数 | P50 | P95 | 采样时长 |
| --- | ---: | ---: | ---: | ---: |
| 预热，两波 | 1,000 / 1,000 | 411.1 ms | 1,302.9 ms | 1.859 s |
| 写入期间查验 | 3,000 / 3,000 | 300.3 ms | 387.3 ms | 2.884 s |
| 作业提交 | 10,000 / 10,000 | 80.2 ms | 137.0 ms | 35.963 s |
| 写满后查验 | 3,000 / 3,000 | 230.0 ms | 306.9 ms | 2.188 s |

所有阶段均为零拒绝、零超时、零错误。前两轮使用 24 个 PHP 开发服务器进程及反向代理，混合查验 P95 分别为 562 和 586 ms。上表是换用 FastCGI 工作进程后的结果。冷启动的预热数值独立列出。此次数据覆盖 1 万次提交和 25 个凭证编号，跨主机网络和更大凭证库须在目标部署另测。

重跑时使用独立的 `learning_test_*` 库，先迁移再启动多进程 HTTP 服务。在 Python 环境安装 aiohttp，设置与 Web 相同的数据库环境变量，在仓库根目录运行以下命令。

```sh
python tests/practicum_capacity.py http://localhost:8088 ./capacity-results
```

## 旧租户升级

从 v1.1.0 标签建库并运行港湾培训示例，保留一名实际完成课程的学员，另加一条历史结业样本以覆盖跨批次恢复。回填前启用会被拒绝。每次回填一条，在不同进程中执行第二批及重复批次，最终重复导入数为零。首笔岗位标准发布后停止 HTTP 进程，重启时重发同一请求，返回同一业务编号。暂停期间可回读原回执，新写入被拒绝。将含实训业务的数据库备份恢复至另一空库，逐表比较 64 张表，并通过 HTTP 重读旧课程证书、已撤销的岗位凭证和已提交的量规。
