# 结业证书与到期复训

## 结业审核和签发

教务在班期报名详情打开「结业审核」，逐项核对学员是否满足以下条件。

- 报名处于已报名或学习中，并且总学时和各章必修学时均达到课程版本的要求。
- 班期已发布的必修作业均达标。每份作业以最新提交版本的评分为准。
- 按班期绑定的课程版本计算考试成绩。取最高分或最近场次得分，成绩必须及格，所有已开始的考试须完成评分。

工作台的证书有效期默认填入 365 天，可设为 1 至 3650 天。签发时，系统在同一事务内保存证书、签发当时的审核证据和审计事件，并将报名标记为已结业。同一报名只能签发一张证书。以相同有效期重试会返回原证书，尝试改变有效期会收到冲突响应。

学员可在「我的报名」查看本人证书和审核证据，打印证书或分享查验链接。查验页 `/verify?serial={serial}` 无需登录，只展示证书编号、签发机构、课程和版本、签发及到期时间、当前状态。日期使用 UTC，状态由当前时间和撤销记录决定。教务可填写原因撤销证书，工作台保留撤销原因与审计记录。

## 到期复训

部署时，用同一应用环境变量定期运行以下命令，例如每分钟一次。处理上限可按部署规模调整。

```sh
php bin/learning.php credential-sweep 100
```

证书到期后，可立即通过查验页看到「证书已到期」。扫描程序为到期且未撤销的证书创建一条待复训任务，重复或并发执行沿用同一条记录。该任务在教务和对应学员的「复训任务」中可见。

教务把任务关联到证书持有人在同一课程其他班期的新报名。报名须在原证书到期时或之后生效，状态须为已报名或学习中。原关联报名在退课或换班后可改绑有效报名。新报名满足结业条件并获签发后，复训任务完成，记录连接原证书、新报名和新证书。原证书撤销时，系统会取消尚待处理的复训任务。

## HTTP 接口

工作台接口沿用会话和 CSRF 令牌。复训列表用 `after` 翻页，返回 `next_after`。`state` 支持 `all`、`pending`、`enrolled`、`completed` 和 `cancelled`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/credentials/enrollments/{enrollment}` | 学员查看本人审核和证书，教务查看本机构的报名 |
| `POST /api/credentials/enrollments/{enrollment}/issue` | 教务输入 `valid_days` 签发 |
| `POST /api/credentials/{credential}/revoke` | 教务输入 `reason` 撤销 |
| `GET /api/credentials/retraining` | 查看本人或本机构的复训任务 |
| `PUT /api/credentials/retraining/{task}/enrollment` | 教务输入 `enrollment_id` 关联报名 |
| `GET /api/verify-credential/{serial}` | 匿名查验证书 |

## 复跑验收

对独立的 `learning_test_` 数据库执行迁移并启动工作台，再运行以下用例。测试通过临时修改合成证书的时间来模拟到期。

```sh
python3 tests/credentials_http.py http://127.0.0.1:8080
```

用例覆盖 600 秒学时、必修作业、首考 55 分和补考 78 分，验证六个独立 MySQL 连接并发签发只生成一张证书，六个并发扫描只创建一条复训任务。用例还检查匿名查验的数据范围、机构与学员的数据权限，以及核验状态、复训换证和撤销。
