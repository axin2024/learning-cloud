# 岗位实训

以设备点检班为例，组长交一份全组共用的点检报告，装配员和核查员分别上传个人记录。导师可以查看组员各自领到的材料、提交记录和仍缺的维度。学员能下载本组的共用作品和本人的个人作品。

## 工作台操作

1. 教务打开“班期 → 岗位实训 → 发布岗位标准”，录入维度代码、权重、达标分和证据归属。权重合计为 100%。在“选择并冻结评分标准”里选定此班使用的版本。后续发布替代版本时，在读班保留已冻结版本。
2. 导师从“授课班期 → 岗位实训”发布任务书、参考样例和 UTC 截止时刻。在任务详情分派小组，逐人填写职责和独立材料。分派一人即可用于个人实训。
3. 学员进入任务详情，记录个人贡献并上传作品。文档标记页码，图片标记百分比坐标和宽高，视频标记起止毫秒。每个文件上限为 2 MiB。服务器计算原始字节的 SHA-256。
4. 任一组员都能选择文件并提交本组作品。提交时保存所选文件对应的标注和每名组员的贡献版本。缺少个人贡献会退回草稿，回执列出缺失成员。已记录贡献、但个人证据尚不完整时会保存提交，并按成员列出待补维度。
5. 超期时，学员先申请补交，导师逐次批准并指定新的截止时刻。提交回执保留迟交标记。再次提交会新增一个版本，原版本可继续查看和下载。

## 匿名双评

教务从冻结回执打开“评审与定分”，对照原件核查页码、图像区域和视频时间段，逐件填写匿名说明。图片须附上已遮盖可识别信息的选区，视频须选取 0.1 至 8 秒的匿名片段。工作台只提取 RGB 画面，保留纵横比，最长宽高分别为 320 和 240 像素，视频每秒约三帧。评委可播放、暂停、逐帧定位。文件名、声音和容器元数据不进入评审件。制备人仍须核对画面本身是否含有工号、人脸或手写签名；细小读数应先裁剪放大。

教务分别指派两位评委。制备人、班期授课人员、同组成员和已占用另一个席位的评委无法接单。评委从“匿名评审”填写每个维度的分数与理由并锁定。两份评分都锁定后，超出阈值的维度交给第三位评委；其他维度取均值。总分按权重计算并保留一位小数。学员只可查看自己的结论。

## 提交接口

`POST /practicums/{id}/submissions` 接收登录会话、`X-CSRF-Token` 和 `Idempotency-Key`。请求提供数字类型的 `team_id`、`attempt`、`rubric_rev` 及文件摘要数组 `artifact_hashes`。尝试号从 1 连续递增。客户端可以从该组的 `GET /api/practicums/{id}/teams/{team}/artifacts` 选择已上传文件的实际摘要。

| 场景 | HTTP | 回执或处理方式 |
| --- | --- | --- |
| 提交成功，或原请求按原幂等键重试 | 201 | `submission_id`、`submitted_at`、`late`、`missing_evidence`、`evidence_manifest`、`manifest_digest`、`changes` |
| 缺少必交的团队作品 | 422 | `team_evidence_required`，含维度名称 |
| 缺某人的贡献记录 | 422 | `contribution_required`，含成员编号和个人维度名称 |
| 待批、批准已过期，或批准的是另一次提交 | 409 | `late_approval_required` |
| 同一幂等键对应不同请求 | 409 | `request_key_conflict` |

从 `GET /api/practicums/{id}/teams/{team}/submissions/{attempt}` 可重读任一版本。清单摘要使用 UTF-8 JSON，递归按对象键名排序，保留数组顺序，不转义 Unicode 或斜杠，省略分隔空格，然后计算 SHA-256。数据库备份同时包含原始文件、标注、贡献修订及已冻结清单。

## 一名学员补证后如何计入部门覆盖率

在工作台打开学员的评审结果。两名同组同学已经取得凭证，第三名学员的独立核验记录缺失，此时应认证 3 人，达标 2 人。学员重新交件后，选择「核验」维度，引用补证所在的提交版本，并填写申诉说明。复核人在该维度内查看原评分理由、定位标注和补证，记录维持或改判的理由。原评委投票保留。缺少所需附件的版本无法用来消除证据缺口。

改判满足岗位要求后签发凭证。若同一学员已有有效的上一版，新凭证关联原编号。学员可分别选择是否向公众展示岗位标题和分数。扫码者无需登录，撤销后，新旧编号都只公开状态和失效日期。

在「企业购课 → 岗位能力盘点」选择部门和岗位。分母取该部门应认证的在职员工，分子按持有效合格凭证的员工去重。此例从 2/3 变为 3/3。与复训任务关联的个人分数从 72.5 提高到 80.0，变化为 +7.5。披露人数不足时隐藏人员细项。空间管理员设置岗位名册、在职状态和披露下限，企业管理员可在授权企业内读报表并安排复训。

| 业务动作 | HTTP 方法和路径 |
| --- | --- |
| 读评审结果及凭证链 | `GET /api/practicum-reviews/cases/{case}/certification` |
| 发证、撤销 | `POST /api/practicum-reviews/cases/{case}/credential`、`POST /api/practicum-reviews/cases/{case}/revoke` |
| 选择公开字段 | `PUT /api/practicum-reviews/cases/{case}/disclosure` |
| 发起、审理单维度申诉 | `POST /api/practicum-reviews/cases/{case}/appeals`、`PUT /api/practicum-reviews/cases/{case}/appeals/{appeal}` |
| 扫码查验 | `GET /api/verify-credential/{serial}` |
| 查看岗位覆盖率、布置复训 | `GET /api/companies/{company}/competencies/{plan}`、`POST /api/companies/{company}/competencies/{plan}/training` |
| 学员查看自己的复训任务 | `GET /api/me/competency-training` |

## 在测试库复跑

使用项目的 PHP、MySQL 和 Python 环境，令 `LEARNING_DSN` 指向独立的 `learning_test_*` 数据库。执行迁移并启动 HTTP 服务后运行以下命令。每次运行创建独立租户，覆盖新旧班期、三人分工、跨组读权限、补交审批和两版交付差异。

```sh
python tests/practicum_http.py http://127.0.0.1:8088 acceptance.json
```

输出文件包含三人组的首次提交、补证回执、改判结果、部门覆盖率和撤销后的公开读数。[查看一次实测回执](practicum-acceptance.json)
